## What the last builds found

**The warning's receipt didn't open yet.** When the warning flagged a claim, it printed a `thruline why` id for it. That id only became findable after the session ended and the record was filed. So 5 of 81 ids failed to open at the exact moment we told you about them. Now `why` also reads the live record. Looking up an id that isn't there used to take 79 seconds on a big record. It now takes 0.38.

**The warning spoke twice, and sometimes when it shouldn't.** For one unbacked claim, the warning and the next-session brief could both mention it. And one honest case, `node --check` followed by "The build passes.", got flagged. The first is fixed: if the warning already told the agent, the brief stays quiet about that claim. The second we kept on purpose. A syntax check passing isn't the build passing, so the flag is true.

**Undo left files behind.** After `thruline init --undo`, six files ThruLine had written were still there. Undo now removes everything ThruLine wrote, judged by what ThruLine itself recorded writing. Anything it didn't write stays, and undo names it.

**A fix for Node projects broke Python ones.** We added a better answer for Node projects with no test script. The reviewer found it would also catch Django, Python, Go and Ruby projects that happen to have a `package.json` file, and stop counting their real test runs. Fixed before it shipped: the Node rule now applies only when no other language's project files are there.

**One of our agents posted a stale status.** The agent that assembles builds said two pieces were still missing, when both had been delivered two hours earlier. Its file reader had skipped those lines. Nothing broke, but the release candidate sat unbuilt for two hours. A tool about agents' stale claims, held up by an agent's stale claim.

## Written down, not hidden

Three things we couldn't fix before the release go in the release notes and the README, in plain words:
- **Test-tool wrappers.** To record test runs, ThruLine adds a small wrapper for each supported test tool. So `command -v pytest` finds the wrapper even if pytest isn't installed. Running it still fails, as the missing tool would.
- **Two ids for one claim.** With more than one agent session open on the same Mac, the claim id shown in a session can differ from the one HQ shows for the same claim. Both open with `thruline why`.
- **Unreadable `package.json`.** A project whose `package.json` isn't valid JSON may be offered a check that can't run there.

All three are on the 0.3.1 list.

## The release candidate
- **Tests:** 7,074 Rust tests and 3,471 UI tests, 0 failures.
- **Launch test:** passed twice in a row with the screen unlocked. It checks that the app starts hidden, with no Dock icon flashing.
- **Release-day dry run:** the whole Mac app release ran end to end, minus the real signing keys. The update file it produces carries the new Known limits.
- **Speed:** the warning adds about 0.16 to 0.18 seconds at the end of an agent's turn.
- **Size:** 21.9 MiB download, 57.4 MiB installed, 19.0 MiB for an in-app update. These numbers are now the budget, and 0.3.1 can't exceed them.

The code is frozen. Only a fix that would stop the release gets in.
