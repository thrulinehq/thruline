# Day 17 · 5 Nov 2026 · A run that tested nothing called our agent a liar

**TL;DR:** We signed r19, installed it from /Applications, and pressed **Check it again** on a real project with a real `~/.zshrc`. Yesterday's fix held: ThruLine found cargo and ran `cargo test --locked`. Then the build failed, because one dependency downloads a prebuilt library at build time and ThruLine runs checks offline. Zero tests ran and no test count was recorded. ThruLine marked the agent's statement **Contradicted** anyway, and the whole Change went red with it. The statement was about a different test suite, too: the npm worker tests, not the Rust ones that tried to run. Yesterday we fixed this for the lines you accept. We missed the agent's own sentences. That is the one thing this tool must never do, so it gets fixed before anything ships. The same day, the payment path worked end to end in Stripe test mode, and our own release guard stopped a deploy for a reason our own config comment said couldn't happen.

The error ThruLine kept only a fingerprint of, reproduced by hand with the same program, folder and settings:

```
error: linking with `cc` failed
... ort-sys was instructed not to download prebuilt binaries
```

ONNX Runtime's Rust bindings fetch a prebuilt library while they build. ThruLine runs every check with `CARGO_NET_OFFLINE=true`. From a normal terminal, with the network, the same tests build in 91 s.

## Three wrongs in one word

1. **It counted a run that tested nothing.** No test ran, so the run settles nothing. ThruLine's own vocabulary has a word for that ("Couldn't check"), and it didn't use it.
2. **It checked the wrong suite.** The agent was talking about the licence Worker's npm tests. ThruLine ran the project's Rust tests. Even a perfect run of those couldn't prove or disprove that sentence.
3. **It said it without showing why.** The 27 KB of build output was reduced to a hash. After the run, nobody could see what failed, and the sheet said the message to the agent "names the failing test" when there was no failing test.

## Where the word came from

Not from the engine that judges claims. That reads only the rows written by the agent's own command shim, joined on the agent's session, and a run ThruLine starts never lands there. The flip was on the screen side. A function that builds the check sheet (`sheetProof` in `ui/src/hq/data/change.js`) took the pass or fail of the latest ThruLine run and applied it to the agent's statement, with no check of which tests the statement was about.

Yesterday we fixed the same mistake on the criterion path. This was its twin on the statement path.

## The fixes going into r20

- **A run ThruLine starts never puts a verdict on an agent's statement.** It settles only the lines you accepted. The agent's statements keep the verdict from the agent's own recorded runs. This also closes the mirror case, an unrelated suite passing and marking a claim **Proven**. Landed, with tests. An independent review reverted the change and 6 tests went red.
- **A run with no test count reads "Couldn't check · settles nothing"**, keeps the first 20 lines of its error output on the record, and doesn't use a free check. When the build needed the network, it says so: "The build needed the network, and ThruLine runs checks offline." In progress.
- **"Would be proven by" shows the command ThruLine runs.** It showed an example command from a fixture instead. Red first, 3 of 5 failing, now 5 of 5.

**Offline stays.** ThruLine doesn't open the network for your build. A per-project opt-in is on the 0.3.1 list.

## Our own guard, and our own comment

The preview deploy refused:

```
Refusing to deploy: dist/assets/auth.js does not name the live licence worker,
so this dist was built for a preview
```

That guard exists so a preview build can never reach thrulinehq.com. The config file carried a comment above it saying no other environment inherits it. That's wrong: in wrangler, the top-level `[build]` is inherited. So the guard did its job on the one deploy it was meant to allow. The fix gives the preview its own build step. The production guard is unchanged, and the comment is being corrected.

Day 14 was a code comment promising a time limit the code never had. Today it was a config comment. Same shape: a confident sentence nothing ever checked.
