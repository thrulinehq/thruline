# Day 8 · 26 Oct 2026 · Over ten thousand tests were green. Installing it like a stranger broke it in two minutes

**TL;DR:** We signed and notarized the Mac app ourselves, and Apple accepted it first try. Then we installed it the way a customer would, and found what over ten thousand passing tests had missed: **a crash on the very first launch**, **a dead screen for anyone upgrading from 0.2**, a first screen that said **"Nothing from undefined is recorded yet"**, and a payment path where **monthly Pro would have quietly switched itself off after about six weeks**. We reopened the release candidate. Nothing merged today. Launch is still 30 Oct.

## The release rehearsal

We ran the real release path end to end on yesterday's release candidate, but kept everything private:

| Step | Result |
|---|---|
| Build and sign with our Developer ID | done |
| Apple notarization | **accepted** |
| Staple and Gatekeeper check | "accepted, source=Notarized Developer ID" |
| In-app update files, signed with our updater key | made and verified |
| Published | **nothing**, on purpose |

The one stumble was ours. A stray Return press went into a hidden password prompt, and signing the update file failed. The script now explains that case properly.

## Then we installed it like a stranger

| What we tried | What happened |
|---|---|
| Open the app on a Mac that used 0.2 | The Inbox showed "could not read the record" and told the user to check a terminal command an app user never runs. The real reason, a one-time record update, was thrown away by the screen. |
| Open the app on a brand-new account | **It crashed on the first launch.** The second launch was fine. |
| Read the first screen as a new user | "Nothing from undefined is recorded yet." |
| Read the help text in the app | Three places told app users to type `thruline …` commands they don't have yet. |
| Follow the money | Buying works. But a paid licence only lasts the period that was paid for, and the app never fetched the next one. Monthly customers would have lost Pro after about six weeks. |

## Why ten thousand tests missed all of it

Think about where code actually runs:

| | fresh | used |
|---|---|---|
| **fake** | our tests | |
| **real** | **a new customer** | **an upgrading customer**, and our own laptop |

Our tests run on clean, made-up setups. Our laptops are real, but they had their first launch weeks ago and they keep up with every version. A new customer is real *and* fresh. An upgrading customer is real *and* behind. Nobody on the team ever sits in either seat, so nothing tested them.

The first-launch crash is the purest case. It happens **once per person, ever**. No developer will see it twice, and most never see it once.

## What changes

- **Two tests every release, from now on:** a brand-new account on the real signed build, and a copy of a real user's old data. Both run on the installed app, not in the test harness.
- **The fixes, test first:**
  - an **Update now** button for records from older versions;
  - the first-launch crash;
  - the "undefined" line;
  - no terminal commands anywhere an app user would read them.
- **Accounts for Pro.** You sign in with your email on thrulinehq.com, using a one-time code. The app notices by itself. When you pay, it switches to Pro by itself and renews by itself. Free use still needs no account.
- **Payments get tested without spending money:** Stripe's test mode can skip ahead through a month of renewals, failed cards and cancellations in minutes. One real purchase comes at the very end.
- **Every screen we add for accounts is designed first and walked on the real build,** and is measured against a budget: download to Pro in under 3 minutes, no terminal, no copying keys.

## Merged today

Nothing. The release candidate from Day 7 was frozen and green. It just wasn't tested from where a customer stands.
