# Day 9 · 27 Oct 2026 · 76% of our statements could never be proven, and 1,311 sessions were recorded but never read

**TL;DR:** Two outside reviews of the app on a real record gave us 93 findings. We traced every one to the code and found most come from 8 causes. The two worst: the dashboard's "0 of 3,660 proven" counted 2,789 statements that **nothing could ever prove**, and the recorder kept recording every day while **nothing had read a session since 7 Oct**. Neither showed up in thousands of passing tests.

## The headline that could never move

The dashboard said **0 of 3,660 statements are proven**. It looks like an agent that lied 3,660 times. It wasn't.

| | statements |
|---|---|
| "Recorded only": claims like "done" or "all set" | **2,789** |
| No proof in the record | 853 |
| Needs a re-check | 18 |
| Proven | 0 |

76% of the denominator were claims that nothing can check until someone says what "done" means. They could never become Proven, so the headline could never move.

**The fix:** the headline now counts only statements that can be checked (871 here). "Recorded only" gets its own line and a button to say what done means, which turns a claim into checkable lines. Nothing is promoted to look better: Recorded never counts as Proven.

## The recorder recorded. The reader stopped.

| | |
|---|---|
| Hook events written, 7–26 Oct | **372,904** |
| Claude Code sessions newer than the record | 1,121 |
| Codex sessions newer than the record | 190 |
| Sessions read into the record since 7 Oct | **0** |

The hooks never stopped, so everything that watched "is it recording?" said yes. What stopped was the step that reads transcripts into the record: it only ran when someone pressed "Load every session" during setup, and nothing ran it again. The part that was alive was the part we were watching.

**The fix:** read new sessions on start, after an update and as they arrive; find new project folders by themselves; and a check that compares what was recorded with what was read, so a gap like this says so within minutes instead of 20 days.

## Other root causes worth sharing

- **Clicking a row only highlighted it.** Opening was keyboard-only, and everyone testing used the keyboard. Every key action now needs a click action, and a test walks the whole path with clicks only.
- **Checks started from the app couldn't find `cargo`, `npm` or `pytest`.** A Mac app opened from the Dock doesn't get your shell's PATH. ThruLine now reads your login PATH once and uses it.
- **One word meant two opposite things.** "Not proven" meant both "the run failed" and "nothing ran". It's now **Contradicted** and **Not checked**.
- **Project names showed folder codes** like `-Users-…`, because the name came only from the 5 newest live transcripts.

## What we changed in how we work

- One ledger: every finding, its root cause in the code, a failing test first, then the fix.
- A census in the release check for terminal commands in the app: anyone using ThruLine should never need Terminal.
- Two tests every release that we never ran before: a brand-new account on the real build, and a copy of a real user's old data.

## Merged today
- "Check it again" opens one sheet (it opened two), and the first press starts tracking the work.
- "What counts as done?" no longer renders hundreds of step numbers over the page.
- The first link of the chain reads the same on every screen.
- The release check on the combined build went red on 3 tests that fail only under load. They pass alone. They're being traced, not re-run until green.
