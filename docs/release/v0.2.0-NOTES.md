# ThruLine 0.2.0 — release notes (draft for sign-off)

These notes describe the source frozen for 0.2.0: the private main line at `688868ba` (the code freeze was `0992b108`; three later corrections are described next), with the version set to 0.2.0 and these release documents added on branch `hq-next/v02-release` (that branch was at `b600eede` before this documentation commit). The three corrections: ⌘↵ inside the Approve sheet records no decision, so Approve needs an explicit press (`a01cb3c4`); the Change Brief's Plain / Technical button keeps its visible name (`1a1741c7`); and the Approve sheet, What counts as done and Every statement judge whether the bar was set after the work on the recorded moments, not on clock times (`9a33c88a`, `0b4d0b97`). The release candidate is the commit that carries this text, and the founder confirms the launch commit; these notes do not state the full-gate result, which is run on that commit afterwards. Nothing has been published. The founder sign-off sheet (`signoff/v0.2/FOUNDER-SIGNOFF.md`) lists what has to be accepted first, and `docs/decisions/INSTALL-DAY.md` is the install-day checklist.

## What's new

- **One place to review the work.** The Inbox, Change Brief, every statement, changed files, what counts as done, re-checks, approvals, the whole story, record over time, Team and a pull-request preview are connected. A link opens the screen it names, and a read that fails shows its error inside the app instead of replacing the page.
- **Decisions you can check again.** Words a person accepts become a versioned check. Proposals, accepted settings, findings and later revisions stay separate, and Verify says what the record can and cannot establish.
- **Project recording controls.** First run installs only the capture parts you pick, for the project you pick. Settings can pause capture of sessions that start during the pause, hide paths from what is shown and exported, and manage run permission folder by folder.
- **Your own review stays in the record.** Notes, a second approval, an objection beside a statement, and a message copied for the agent can be recorded without changing any verdict by implication.
- **Find, navigate and export.** ⌘K searches the recorded work and offers answers drawn from it; the keyboard map and Settings list the keys. The whole story can be saved as Markdown, HTML or JSON, including a redacted copy, and Record over time can export CSV.
- **Keep the Inbox current.** A Change that is ready appears for approval, a running agent is re-read, and a hidden thread comes back if its recorded events change. Each Change can re-check the sessions it confirmed.
- **Optional reminders while HQ is open.** HQ can notify you when a Change is ready for your approval, when an agent's "done" is not backed by the record, when an agent is waiting for an answer, and when recording stops. A weekly summary can show the previous seven days when HQ opens. All of these are off until you turn them on.
- **No trial.** Everything is free except approving a version, which needs a Pro licence. A leftover trial file from 0.1.0 is ignored and left exactly as it was.

## Upgrading from 0.1.0

- **Run `thruline upgrade` once, after backing up your record.** Until you do, every other command stops with "schema upgrade pending" and exits 3 without changing anything.
- **What it did on a rehearsal copy (12 October 2026).** The copy was a clone of our own largest record: 11.0 GiB, 2,762,929 events across 97 projects. The upgrade took 36 seconds. Every table that already existed kept every row (the one change is the upgrade's own schema stamp), and 14 new tables were added, all empty. Running `verify` afterwards gave the same per-project results as before the upgrade: the same 90 projects pass, there are no chain mismatches, and the other 7 projects show the same counts under the new wording described next.
- **`verify` can now exit 2 where 0.1.0 exited 1.** Acceptance means the same per-project classification as before the upgrade: 90 PASS / 7 source gone / 0 chain breaks. For those 7, exit code 1→2 (UNVERIFIABLE) is the expected vocabulary change, not a regression. If the original session files for a project are gone, 0.1.0 reported a mismatch (exit 1). 0.2.0 reports the same counts as **unverifiable** (exit 2), because a missing original is a check that cannot be made, not a check that failed. It does not mean the record is damaged, and it does not mean the project was checked and found intact. In the rehearsal, 7 projects were affected and their counts were identical under both versions. Keep the finding; do not treat exit 2 as "intact".
- **Check free space yourself.** The upgrade requires free space at least the size of your record, and the free-space figure it prints is the volume's available capacity, which can read higher than `df` (72.5 GiB against 46 GiB in the rehearsal). Take the number from `df -h`.
- **One limit of the rehearsal.** It ran without access to the original session folders, so it could not exercise the comparison against original files. On a real record, the labels for "original gone" and "original grew after it was recorded" should appear.

## Fixed since the previous draft

- Change Brief's **Open in editor** now works on real Changes (it was always disabled), and it still keeps your home-folder path out of the page. The link is built only when you click it.
- `thruline ui` no longer stops when whatever started it stops reading its output.
- Settings: thirteen corrections from the screen-by-screen check. For example, **Read again** now re-checks the capture health of the selected project as well as the Codex watch, notification switches respect the browser's permission, and the weekly summary switch is named for what it shows.
- Inbox: when a Change's target version changes, the command it tracks is refreshed instead of staying on the old one.
- Record over time: the three statement counts now open a list of those statements across Changes, one line per statement with a link to its Change. The list shows the receipt id, because the summary does not carry the statement's words.
- Record over time, Capture: the card says which problem it found (Codex capture off, Codex not answering, Codex watching a different folder, or capture could not be read), and **Try again** shows "Checking…" until the new read returns instead of announcing the result early.
- Further screen repairs: Repair Loop failure states and shortcuts; What Changed reflecting stopped runs and later edits; Approve sheet staying on the committed version with the exact withdrawal; Every Statement routes, proof and views; Step View showing agent messages that could not be classified; Command Ask search, copy and palette keys; and the pull-request preview's "Check this receipt" button, which runs the verifier on a disposable copy and writes nothing to your repository.
- Change Brief: **.** and **y** now press the buttons the panel shows (Check it again, Tell the agent), including when the agent's own "fixed" claim is selected.
- Keys: a held **?** no longer closes the key map it just opened, and a held **g** no longer cancels its own wait.
- Find, ask, act: the Esc that closes it no longer also goes back a screen.
- Inbox: **Check it again**, **Tell the agent** and **Copy it again** always name the row's thread (the address could switch a moment after it was drawn, so the same press could go to two places); a finished thread whose Change is approved for its current version reads **Approved** (it read "Nothing open"); and a quote says "HH:MM · step N" instead of "yesterday · step N".
- Settings: hooks that point at a missing program now raise the system-state bar ("Hooks not firing", "Not recording"); "Installed by thruline init" appears only where it is installed; the Rules link names a Change and opens its What counts as done; and the time on an allowed folder says which day it belongs to.
- Settings now shows the **HQ stopped** bar when HQ stops. Settings checks every 3 seconds, and only while Settings is open and the page is visible.
- The top-bar **Recording** pill follows the Change you are looking at. On a Change screen it used to count every live agent session on the machine.
- A folder ThruLine has never recorded shows its folder name with "path not known until the first recording" instead of a guessed path (a folder like ~/my-app could show as ~/my/app). ThruLine installs no hooks into a folder whose path it does not know.
- Just after midnight, the Approve sheet, What counts as done and Every statement could misjudge whether the bar was set after the work, because they compared clock times; they now compare the recorded moments.
- Folders that were shown inside a similarly named folder now show on their own.

## Not in v0.2

- **Removing a project's records.** Settings shows the row disabled and says removing is not available in this version. ThruLine 0.2.0 removes nothing from your record. The work is parked for 0.2.1. The upgrade still creates the empty table that will hold removal receipts; nothing writes to it.
- Template **Offer** and **Stop** in Settings: you can list and preview committed templates; changing which are offered needs a reviewed policy edit that is not built yet.
- What counts as done: a durable **Drop** receipt, and **Link/Unlink before acceptance**. The record cannot back those claims yet.
- Opening the Inbox within two seconds on a very large record (see the first known limit below), planned for 0.2.1.

## Known limits

- On a 97-project, 76,765-session, 2,762,929-event test record, the Inbox took about **3.4 seconds** to open (3,397 ms measured). This measurement does not describe smaller records.
- Notifications arrive only while HQ is open. Three of the four follow the project currently open; "Not backed" uses its own feed. A recording stop that happened while HQ was closed is not replayed later, and two open tabs may each show the same notification.
- A Change's integrity check re-reads the sessions that Change confirmed. It does not re-read original source files, and it does not prove that a saved export has stayed unchanged.
- Record over time, Capture: after a problem card has gone away, a later problem can start by showing an old "Tried again at …" line before you have pressed **Try again**. Pressing **Try again** replaces it with a fresh result. A display problem only; it changes nothing that is recorded.
- `thruline upgrade` prints the volume's available capacity as its free-space line. It said 72.5 GiB where `df` said 46 GiB. Wording only; take the number from `df`.
- Decisions: this release ships without the local shipping proof (it needs all four downloads, and the two Linux downloads could not be built on the release machine). The only effect is that changes under `docs/` are not set aside, so Decisions can show more findings than strictly needed. Your revision-6 acceptance (its path waivers) is how those are set aside.
- Installing hooks from HQ, or with `thruline sensor install`, while HQ runs on a non-default `--db` still points the hooks at `~/.thruline`. Use `thruline init --db <path>` instead.
